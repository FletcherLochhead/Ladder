### SaaSathon Info

### Event Overview

SaaSathon is a two-day hackathon where teams build a productivity SaaS product from idea to working product, then pitch it to the rest of the event and the judges.

The event is brought to you by Lumin, in partnership with Entre, with support from OpenAI's Codex Ambassador program, FundTap, and Partly.

Justus is the event organiser and MC. He is a software engineer at Lumin and the local Codex Ambassador.

The event runs from Friday 8 May to Sunday 10 May 2026. Teams may stay as long as they want during the event. Snacks and drinks are available around the clock, and catering will be provided.

### Theme

Build a productivity SaaS product that uses AI in creative or non-conventional ways.

The SaaSathon is about creating practical SaaS products that help people get meaningful work done faster, better, or with less operational drag. Any productivity software idea is welcome if it gives a person, team, business, creator, student, or organisation a better way to complete useful work.

AI should be part of the product's ability to do useful work for the user. A chat box alone is not the goal. Teams should use AI to understand context, make decisions, automate steps, reduce manual effort, or create outcomes the user would otherwise need to produce themselves.

Creative and non-conventional are intentionally broad. In practice, this mostly means teams should build something beyond a chat box or basic chat agent. Teams can build something serious, niche, unusual, playful, or weird if it still helps someone do useful work. The product does not need to look like an existing productivity tool.

### What Teams Should Build Toward

- A SaaS product or SaaS MVP that solves a clear productivity problem.
- A deployed product that judges and other contestants can access.
- A live demo path that works during the presentation.
- One or more AI features or functions.
- A workflow where AI meaningfully improves the user's outcome, not just the interface.
- A product a real person or team could understand, try, and eventually pay for.
- A focused experience that works end to end for one valuable use case.

### Strong Theme Fit

Strong projects might help users:

- automate repetitive work;
- turn unstructured information into useful actions, records, summaries, documents, or decisions;
- collaborate more effectively across teams, files, tasks, or customer interactions;
- manage documents, approvals, forms, reporting, planning, support, operations, learning, finance, sales, marketing, scheduling, or internal workflows;
- move from intent to completed work with fewer manual steps;
- make better decisions by combining context, data, and AI-assisted reasoning.

### Weak Theme Fit

Projects are weaker fits if they:

- are mainly a generic chatbot with little product workflow around it;
- use AI only as a decorative feature or marketing claim;
- solve a vague problem without a clear user, task, or value;
- feel like a one-off demo rather than the start of a SaaS product.

### Requirements

Every team needs these things by Sunday lunchtime:

- GitHub repo: the project should be in a GitHub repository that will be shared as part of the submission.
- Deployed project: the project has to be deployed and available for the other contestants and judges to visit during the presentation.
- Live demo: the team needs to show a live view of the project during the presentation to show off the features.
- AI features: the project should have one or more AI features or functions.

### Rules

### Core Build Rules

- Teams need to build and deploy a SaaS product or SaaS MVP.
- Teams need to show a live demo during the presentation.
- Teams need to submit a GitHub repository at the end of the event so organisers can verify the project.
- Teams should build their SaaS product or SaaS MVP during the SaaSathon event window: Friday 8 May to Sunday 10 May 2026.
- Teams may use AI tools, APIs, SDKs, open source libraries, templates, and their own pre-existing material if they have the right to use it.
- Teams must comply with all relevant licence terms, platform rules, and tool allocation rules.
- Teams must not submit material that infringes another person's intellectual property, privacy, confidentiality, or other rights.
- Teams must clearly disclose significant pre-existing work if asked by organisers or judges.
- AI tooling is allowed and encouraged, but teams remain responsible for what they submit.
- Event resources, AI credits, API keys, accounts, venue space, and communication channels must be used responsibly.
- Do not use production secrets, private customer data, or confidential third-party data in a submission unless the team has explicit permission and can use it safely.

### Technology Guidance

Teams can use any stack that works for them.

The recommended setup is:

- TypeScript for safer, faster product development.
- Next.js for building the SaaS app.
- Vercel for the simplest path to deploying a working product.
- Supabase for auth, database, and storage.
- OpenRouter for AI inference inside the product.

This stack is recommended because it is simple, reliable, free or low-cost to start, and well suited to building a fully deployed SaaS MVP during the event window.

Teams are also welcome to use another stack if it gets them to a deployed product with a live demo. The important outcome is a working product, not a particular framework.

### AI and Coding

Teams are encouraged to use AI to build their projects. AI tools are useful for writing code, planning, debugging, design iteration, and creating product assets, but using AI well is still a skill.

This is not just a matter of prompting until the project works. Teams should use AI deliberately, review what it produces, and focus on quality over quantity. The pitch and live demo are only 5 minutes, so a polished core workflow is better than a large unfinished product.

OpenAI will provide each participant with USD $50 in Codex API credits to help build during the event. These credits will be sent out with setup instructions.

Each team will also receive an OpenRouter API key through the SaaSathon dashboard. This key is for running AI functionality inside the team's project.

Teams may also use their own tools, accounts, and subscriptions.

### Dashboard and Submissions

The SaaSathon dashboard is where teams can claim their OpenRouter API key and submit their final project.

Submissions open on Sunday morning and close on Sunday 10 May 2026 around late morning, with the current target deadline at 12:00 pm unless organisers announce otherwise.

Each team must submit:

- a project title;
- a GitHub repository URL;
- a short description of what they built.

A deployed SaaS product is required, and the team must show a live demo during the presentation. The GitHub repository is used for organiser verification and should contain the project code or enough project material for organisers to confirm what was built.

Slide decks are optional. They do not replace the live demo.

The organiser may verify eligibility and submission compliance before awarding prizes.

### Demo Format

- Each team gets a 5-minute demo.
- Judges then have 3 minutes for Q&A.
- Teams should use the demo time to show the product live, explain the user problem, and make clear how AI helps the user complete useful work.

### Judging Criteria

| Criterion | What Judges Look For |

| --- | --- |

| Innovation | Originality, creativity, distinctiveness, and a strong productivity-plus-AI concept. |

| Execution | Product quality, completeness, technical delivery, deployment, reliability, and whether the MVP actually works. |

| Impact and Value | Problem quality, user value, commercial or practical usefulness, and how much meaningful work the product saves or improves. |

| Presentation and Demo | Clear communication, strong product story, effective live demo, and concise answers in Q&A. |
